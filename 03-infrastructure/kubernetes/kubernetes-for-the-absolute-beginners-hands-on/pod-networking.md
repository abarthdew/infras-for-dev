## 단일 노드에서의 파드 IP

- 노드 자체는 SSH 접속 등에 쓰는 IP(예: `192.168.1.2`)를 가진다.
- 도커 세계에서는 IP가 컨테이너에 할당되지만, Kubernetes에서는 **IP가 파드에 할당**된다.
- 파드는 내부 네트워크(예: `10.244.0.0` 대역)에 붙는 자체 IP를 가지며, 같은 노드의 파드끼리는 이 IP로 직접 통신 가능하다.

## 멀티 노드에서의 문제

- 여러 노드가 클러스터에 합류할 때, 각 노드가 동일한 내부 파드 네트워크 대역(예: `10.244.0.0`)을 독립적으로 쓰면 **파드 IP가 충돌**한다.
- Kubernetes는 클러스터를 구성할 때 이 문제를 자동으로 해결해주지 않는다 — 별도의 네트워킹 솔루션을 직접 구성해야 한다.

## Kubernetes의 네트워킹 요구사항

Kubernetes가 기대하는 네트워킹 솔루션의 기본 조건:
- 클러스터 내 모든 컨테이너/파드는 NAT 없이도 서로 통신할 수 있어야 한다.
- 모든 노드는 모든 컨테이너와 통신할 수 있어야 하고, 모든 컨테이너는 모든 노드와 통신할 수 있어야 한다.

## CNI 솔루션

- 직접 구현할 필요 없이 사전 구축된 여러 CNI(Container Network Interface) 솔루션을 사용한다 — 예: Flannel, Calico, Weave Net, Cisco ACI, VMware NSX(가상화 환경).
- CNI 솔루션은 노드마다 서로 다른 서브넷 대역을 할당해 IP 충돌을 방지하고, 모든 파드·노드를 아우르는 가상 네트워크를 구성한 뒤 라우팅 규칙으로 파드 간 통신을 가능하게 한다.
- 이렇게 구성하고 나면 파드는 클러스터 어디에 있든 할당된 IP로 서로 통신할 수 있게 된다.
