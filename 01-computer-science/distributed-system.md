# Distributed System

## 목차
- 분산 시스템이 필요한 이유
- 노드와 클러스터
- 네트워크 실패
- 복제와 샤딩
- 일관성과 가용성
- 합의 알고리즘
- 메시지 큐와 이벤트
- 관측 가능성

## 기초 개념
분산 시스템은 여러 컴퓨터가 함께 하나의 시스템처럼 동작하는 구조다. 서버 한 대로 처리하기 어려운 트래픽, 저장 용량, 장애 대응을 위해 여러 노드에 역할을 나눈다.

```text
client
-> load balancer
-> app node 1
-> app node 2
-> database cluster
```

분산 시스템의 핵심 난점은 네트워크가 항상 믿을 수 있는 것이 아니라는 점이다. 메시지는 늦게 도착할 수 있고, 중간에 사라질 수 있고, 어떤 노드는 살아 있지만 다른 노드에서는 죽은 것처럼 보일 수 있다.

먼저 알아야 할 개념은 다음과 같다.

```text
node          시스템을 구성하는 개별 컴퓨터 또는 프로세스
cluster       여러 노드가 모인 집합
replication   데이터를 여러 노드에 복제
sharding      데이터를 여러 노드에 나누어 저장
consistency   여러 노드가 같은 값을 보장하는 정도
availability  시스템이 요청에 응답할 수 있는 정도
partition     네트워크가 갈라져 일부 노드끼리 통신하지 못하는 상황
```

## 간단한 예시
사용자 요청을 두 대의 앱 서버로 나누는 구조를 생각해보자.

```text
browser
-> load balancer
-> app-1
-> app-2
```

앱 서버는 늘릴 수 있지만, 데이터베이스가 한 대뿐이면 DB가 병목이나 단일 장애점이 될 수 있다. 그래서 읽기 복제본을 두거나 데이터를 나누는 전략을 사용한다.

```text
app
-> primary database
-> read replica 1
-> read replica 2
```

하지만 복제를 하면 "방금 쓴 데이터가 모든 복제본에서 바로 보이는가?" 같은 일관성 문제가 생긴다.

## 반드시 알아야 할 질문
- 서버를 여러 대로 늘리면 어떤 문제가 새로 생기는가?
- 장애는 왜 예외가 아니라 기본 조건으로 봐야 하는가?
- replication과 sharding은 무엇이 다른가?
- consistency와 availability는 왜 충돌할 수 있는가?
- idempotency는 왜 분산 환경에서 중요한가?
- 메시지 큐는 어떤 문제를 완화하는가?
- 모니터링, 로깅, 트레이싱은 왜 필수인가?
